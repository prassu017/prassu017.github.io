Featured work

An execution engine for wealth advisors

Getting an agent to act is the easy part. The hard part is deciding whether an action is allowed to become real. This is the system I built to answer that, running in production.

agent acts independent check allowed to become real held back, never shipped wrong

The trust boundary

Agents pull custodian balances, update CRMs, and assemble and file client review packets. Before anything reaches a client:

  • Every step is limited to a scoped set of tools
  • Writes wait for human approval
  • A separate probe re-derives each value from the source of record
  • If a check can't pass, the result is withheld, not shipped wrong
  • Rolled out behind layered gates: per-workflow flag, org allowlist, kill switch

What a verified run looks like

The agent and the probe work separately. The run only passes when they agree.

How I build

Principles I actually use

Habits that came from real incidents, not a style guide.

01

Fail closed

If the system can't prove a result is right, it holds it back. A confident wrong answer is worse than no answer.

02

Measure the measurer

I once saw a model that had stopped responding score as a slightly weak one. Evaluation needs its own failure modes tested.

03

Replay everything

Every run leaves a record of what ran and why, so problems get debugged from evidence, not memory.

04

Own the whole path

From the customer conversation to the deploy and the fix when something breaks. The job isn't done when the PR merges.
